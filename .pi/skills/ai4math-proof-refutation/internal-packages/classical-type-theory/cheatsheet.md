# Cheatsheet

## Method Router

| If the problem looks like... | Use first | Escalate when... |
|---|---|---|
| terms differ only through lambda application | normalize / Ch 2 | then higher-order unification / Ch 8 |
| Skolem witness may depend on higher-order terms | dependency-safe Skolemization / Ch 3 | dependency relation if terms get unwieldy |
| need a compact proof certificate | expansion proof / Ch 6 | search generator / Ch 10 if instances unknown |
| need human-readable proof | expansion-to-natural-deduction / Ch 7 | merge redundancy before translation |
| unification has many/no mgus or may diverge | bounded search / Ch 8 | deferred constraints / Ch 11 |
| resolution cannot invent a predicate/function | splitting / Ch 11 | primitive/gensub or Z-match / Ch 10, 13 |
| functional/propositional equality blocks progress | extensional resolution / Ch 12 | rewriting/e-unification beyond chapter scope |
| too many type-correct candidates | sorts/subtypes / Ch 13 | annotations, libraries, theorem-specific generators |
| finite type-order cap causes repeated failure | widen cap / Ch 9 | remove cap if completeness matters |

## Decision Rules

- **If Choice is not authorized, then unrestricted higher-order Skolemization is unsafe**, because a Skolem function may become a choice function.
- **If an expansion tree has a tautological deep formula but a dependency cycle, reject it**, because witness dependencies are circular.
- **If no useful instantiation is generated by unification, add structure before adding time**: projections -> primitive substitutions -> gensubs -> context/theorem-specific methods.
- **If higher-order unification exceeds its budget, report bounded failure and preserve alternatives**; do not conclude non-unifiability from timeout.
- **If a clause's constraints are unsatisfiable, delete the clause immediately**.
- **If two constraints share a formula, merge them** to concentrate the unification obligation.
- **If equality/extensionality dominates, change calculus** rather than endlessly expanding ordinary resolution.
- **If a proof is found, preserve its expansion core before prettifying it** so presentation changes do not obscure the proof idea.
- **If a type-order ceiling comes from the theorem's syntax, treat it as unjustified for completeness**.

## Search-Smell Diagnostics

| Smell | Interpretation | Recovery |
|---|---|---|
| same rich candidate terms repeat in equivalent forms | generator redundancy | normalize candidate bodies, use canonical/prenex forms |
| one unification branch consumes all time | unfair scheduling | per-branch bounds + backtracking / deferred constraints |
| proof state grows after every definition expansion | over-unfolding | restore abbreviations; unfold selectively |
| many clauses differ only by unresolved equations | constraint debt | merge/simplify constraints; solve tractable subsets |
| proof object is huge but instantiation pattern is small | presentation redundancy | merge expansion proof, then reconstruct |
| solver says "unprovable" only after bounded search | result overclaim | downgrade to "not found under current bounds" |

## Minimal Validation Checklist

1. Terms are well-typed and normalized where required.
2. Substitution is capture-safe.
3. Skolem/selection dependencies are preserved.
4. Expansion proof: deep formula valid + dependency graph acyclic.
5. Unification timeout is not treated as semantic failure.
6. Choice/extensionality assumptions are explicit.
7. Resource bounds and resulting incompleteness are disclosed.
8. The returned proof can be checked independently of search order/presentation.
