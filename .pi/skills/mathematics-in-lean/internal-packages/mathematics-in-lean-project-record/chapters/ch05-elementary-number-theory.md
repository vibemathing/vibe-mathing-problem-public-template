# Chapter 5: Elementary Number Theory

## Core Idea
Number-theory formalization combines library facts about divisibility/primality with induction and recursion on `Nat`. The central proof-engineering rule is to align induction with the recursive structure of definitions, isolate awkward small cases early, and use specialized arithmetic automation only after the number-theoretic argument is exposed.

## Frameworks Introduced
- **Divisibility decomposition**
  - When to use: a hypothesis `a ∣ b` must become arithmetic data.
  - How: destruct divisibility into a witness equation; rewrite the target; use ring/natural arithmetic. Conversely, prove divisibility by supplying a multiplier.
- **Prime-factor contradiction**
  - When to use: irrational-root or coprimality arguments.
  - How: use primality to move divisibility through products/powers; derive a common divisor; contradict coprimality or the impossibility of a prime dividing `1`.
- **Factorization multiplicity invariant**
  - When to use: equations of powers where parity/divisibility of exponents is decisive.
  - How: apply `Nat.factorization` identities for products/powers, compare multiplicities, then take a modular contradiction. This generalizes the familiar “even vs odd exponent” proof.
- **Induction aligned with recursion**
  - When to use: factorials, sums/products, Fibonacci, custom recursive functions.
  - How: induct on the argument the function recurses on; rewrite the defining equation in each branch; simplify the base; apply the induction hypothesis in the recursive branch.
- **Strong / well-founded induction**
  - When to use: the argument calls on an arbitrary smaller divisor or subproblem, not only `n` from `n+1`.
  - How: use `Nat.strong_induction_on` or well-founded recursion; prove the measure strictly decreases before invoking the inductive call.
- **Generalize-before-induct**
  - When to use: an auxiliary parameter must change during the inductive step.
  - How: `induction n generalizing m`; specialize the stronger induction hypothesis at the new parameter.

## Key Concepts
- **`Nat.Coprime`**: gcd equals one.
- **`Nat.Prime`**: natural-number primality API with divisibility lemmas.
- **`Nat.factorization`**: prime multiplicity as a finitely supported function.
- **Recursive definition**: equations generated by pattern matching on constructors.
- **Strong induction**: induction hypothesis is available for all smaller inputs.
- **`Finset.range n`**: naturals below `n`, central for finite sums/products.
- **`omega`**: Presburger arithmetic automation for natural/integer linear arithmetic.
- **`interval_cases`**: splits a bounded integer/natural variable into concrete cases.
- **`decide`**: closes decidable propositions when computation is an appropriate proof.
- **Well-founded recursion**: recursive calls justified by decrease in a well-founded relation.

## Mental Models
- Use prime factorization as an **invariant extractor**: equality of numbers forces equality of multiplicities.
- Think of induction as **recursive API reasoning**: the proof should follow the defining equations of the object.
- Handle `0`, `1`, or successor cases as **shape normalization** when the general argument assumes positivity/nontriviality.
- Use arithmetic tactics as **side-condition solvers**, not substitutes for divisibility/factorization structure.

## Anti-patterns
- **Inducting on the convenient-looking variable** instead of the recursive argument: the induction hypothesis will not line up with the defining equation.
- **Using natural subtraction/division too early**: side conditions become cumbersome; clear denominators and avoid truncated subtraction when an equivalent additive equation is available.
- **Reproving library primality facts**: inspect `Nat.Prime` APIs first.
- **Forcing ordinary induction on a divisor argument**: use strong/well-founded induction when recursive calls target arbitrary smaller numbers.

## Code Examples
```lean
def fac : Nat → Nat
  | 0 => 1
  | n + 1 => (n + 1) * fac n

example (n : Nat) : 0 < fac n := by
  induction n with
  | zero => simp [fac]
  | succ n ih => simp [fac, ih, Nat.succ_pos]
```
```lean
example {m : Nat} (h : 2 ∣ m ^ 2) : 2 ∣ m := by
  exact Nat.Prime.dvd_of_dvd_pow Nat.prime_two h
```
- **What they demonstrate**: proof structure follows recursion; library primality turns a power divisibility fact into a base divisibility fact.

## Reference Tables
| Situation | Route |
|---|---|
| prove property of recursively defined `Nat` function | ordinary induction on recursive argument |
| recursive call needs any smaller input | strong/well-founded induction |
| parameter changes in step | `generalizing` |
| tiny bounded Nat/Int cases | `interval_cases` |
| linear Nat/Int arithmetic | `omega` |
| concrete primality/gcd value | `norm_num` |
| finite sum/product over first `n` values | `Finset.range` + induction/sum lemmas |

## Section-by-Section Operational Map

**5.1 Irrational roots.** The coprime proof and factorization-multiplicity proof illustrate two formalization styles for the same mathematics. The first stays close to elementary gcd/divisibility and is easy to reuse for arbitrary primes. The second exposes a stronger invariant and generalizes to arbitrary powers, but requires factorization APIs and nonzero side conditions. Choose the proof style whose library prerequisites match the surrounding development.

**5.2 Induction and recursion.** Recursive equations can be used by `rw` or `simp`; `[simp]` annotations make canonical equations automatic. In sums/products over `Finset.range`, clear denominators before induction on natural-number formulas because division on naturals introduces side conditions. Simplifying with associativity/commutativity can canonicalize expressions safely because `simp` orients those rules using an internal term order.

**5.3 Infinitely many primes.** Tiny lemmas such as “nonzero and not one implies at least two” can dominate formalization time; use case splits, `interval_cases`, `decide`, or `omega` appropriately. Strong induction is the natural route for prime-factor existence. The finite-set formulation uses `Finset.filter`, products, and induction. The primes congruent to `3 mod 4` example shows how modular arithmetic, factor extraction, finite products, and contradiction compose in a serious proof.

**5.4 More induction.** Equation-style theorem definitions can mirror recursive functions exactly. Fibonacci examples show multiple base cases, efficient tail-recursive implementations, extensional equality of functions, and `generalizing` for parameters that shift. Well-founded recursion permits recursive theorem calls at any demonstrably smaller argument; Lean can infer simple decreasing relations but can also be given explicit measures.

## Failure Recovery Notes

- If a `Nat` proof is stuck on subtraction, rephrase to an additive equality or use a theorem designed for truncated subtraction.
- If the induction hypothesis is too weak, revert/generalize the parameter before induction rather than trying to strengthen it afterward.
- If a factorization theorem needs nonzero inputs, split the zero case first; it is often trivial by `simp`.
- If modular arithmetic has a tiny modulus, normalize with `Nat.mul_mod`/`Nat.add_*_mod_*` and use `interval_cases` on the remainders.

## Worked Example
For infinitely many primes, formalize Euclid's idea as “for every `n`, a prime exceeds `n`.” First prove any `m ≥ 2` has a prime factor by strong induction: if `m` is prime, use it; otherwise extract a nontrivial smaller divisor and recurse. Apply that result to `n! + 1`. A prime divisor `p` of this number cannot satisfy `p ≤ n`, because then `p ∣ n!`; combining `p ∣ n!` and `p ∣ n! + 1` yields `p ∣ 1`, impossible for a prime. The proof splits naturally into reusable lemmas: lower-bound/prime-factor existence, factorial divisibility, then contradiction.

## Key Takeaways
1. Use library divisibility/primality interfaces before algebraic manipulation.
2. Let recursive definitions dictate the induction variable and rewrite steps.
3. Strengthen the induction hypothesis with `generalizing` when the step changes parameters.
4. Use strong induction for factor/decomposition arguments.
5. Separate number-theoretic structure from arithmetic side conditions; `omega` and `norm_num` are excellent finishers.
6. Alternative proofs can expose more reusable invariants—factorization multiplicity often generalizes better than parity alone.
