# Chapter 10: Linear Algebra

## Core Idea
Mathlib linear algebra is built around bundled linear maps, bundled submodules, quotient spaces, bases as linear equivalences with finitely supported coordinate functions, and dimension as either a natural `finrank` or a cardinal `rank`. Prefer these abstract interfaces before switching to coordinates or matrices.

## Frameworks Introduced
- **Bundled linear-map calculus**
  - When to use: maps between modules/vector spaces.
  - How: work with `V →ₗ[K] W`; apply `map_add`/`map_smul`; compose with linear-map composition; obtain a `LinearEquiv` from bijectivity when appropriate.
- **Submodule map/comap/ker/range**
  - When to use: invariant subspaces, kernels, images, quotients.
  - How: treat submodules as a complete lattice; use `map` and `comap` as a Galois connection; identify `range` as map of top and `ker` as comap of bottom; use kernel/range characterizations for injectivity/surjectivity.
- **Span universal property**
  - When to use: a subspace is generated by a set or a linear map is determined by generators.
  - How: use `Submodule.span_le` to reduce containment of a span to containment of generators; use `span_induction` for properties preserved by linear combinations.
- **Quotient-space lift**
  - When to use: a linear map should factor through `V ⧸ E`.
  - How: use `mkQ`, `liftQ`, or `mapQ`; prove the submodule lies in the kernel; obtain quotient–range equivalences from standard theorems.
- **Basis as linear equivalence**
  - When to use: coordinate representation, constructing maps from basis values, changing basis.
  - How: `Basis ι K V` gives `repr : V ≃ₗ[K] ι →₀ K`; use `Basis.constr` to define a linear map from arbitrary images of basis vectors; use basis extensionality to prove linear maps equal.
- **Matrix bridge**
  - When to use: finite bases make coordinate computation helpful.
  - How: `LinearMap.toMatrix B B'` identifies linear maps with matrices; use `mulVec` relations for action on coordinates; prove basis-independent invariants via change-of-basis identities rather than by entries.
- **Finite vs general dimension**
  - When to use: dimension arguments.
  - How: with `[FiniteDimensional K V]`, use `Module.finrank`; in general use cardinal `Module.rank`. Use explicit named arguments when base field inference is ambiguous.

## Key Concepts
- **`Module K V`**: scalar action satisfying module laws, usually alongside `[AddCommGroup V]`.
- **`LinearMap` (`→ₗ`)**: bundled linear function.
- **`LinearEquiv` (`≃ₗ`)**: linear isomorphism.
- **`Submodule K V`**: bundled linear subspace that coerces to a set/type and inherits a module structure.
- **`IsCompl` / `DirectSum.IsInternal`**: complementary/direct-sum decomposition interfaces.
- **`Module.End K V`**: endomorphism algebra; multiplication is composition.
- **Eigenvalue/eigenspace**: eigenvectors/eigenspaces via kernels of `φ - a • 1`.
- **Minimal/characteristic polynomial**: endomorphism invariants; Cayley–Hamilton uses algebra evaluation.
- **Matrix**: a type synonym/interface for functions `m → n → α` chosen so typeclass inference uses matrix multiplication rather than pointwise multiplication.
- **`Finsupp` (`ι →₀ K`)**: finitely supported functions, the model coordinate space for an arbitrary basis.
- **Universe/cardinal lift**: required when comparing basis index types living in different universes.

## Mental Models
- Linear algebra APIs mirror algebraic ones: **hom → kernel/range → subobject lattice → quotient → isomorphism theorem**.
- A basis is most useful as a **universal property and isomorphism**, not merely a coordinate list.
- Matrices are a **coordinate presentation of linear maps relative to chosen bases**.
- `finrank` is a **finite convenience interface**; `rank` is the general invariant.

## Anti-patterns
- **Dropping to matrices before checking an abstract linear-map/submodule theorem**.
- **Expanding span membership directly** instead of using its universal property/induction principle.
- **Assuming matrix inversion implies invertibility without an `Invertible`/nonzero determinant condition**; matrix inverse is totalized.
- **Using the raw function type for matrices** when multiplication semantics matter; the `Matrix` wrapper selects the intended instances.
- **Forgetting finite support for infinite bases**: coordinates live in `Finsupp`, not the full product.
- **Using `finrank` to reason about infinite-dimensional spaces as if zero meant trivial**.

```lean
example {K V : Type*} [Field K] [AddCommGroup V] [Module K V]
    (B : Basis ι K V) (u : ι → V) : V →ₗ[K] V :=

```
- **What they demonstrate**: linear maps compose as bundled objects, and a basis constructs a linear map from its values on basis vectors.

## Section-by-Section Operational Map

**10.1 Vector spaces and linear maps.** A module is represented by separate additive-group and scalar-action structures; this decomposition is deliberate typeclass engineering. The bundled linear-map type carries map-add/map-smul laws and itself inherits algebraic structure. Product/sum constructions exist both for two spaces and indexed families; direct sums differ from products by finite support.

**10.2 Subspaces and quotients.** A `Submodule` coerces to a set and to a type with its own module structure. The complete-lattice operations encode intersection and generated sum. `IsCompl` handles binary direct decompositions; `DirectSum.IsInternal` handles families. Span is best used through its universal property or `span_induction`. The map/comap Galois connection gives the standard kernel/range tests for injectivity and surjectivity. Quotient-space APIs (`mkQ`, `liftQ`, `mapQ`) mirror quotient groups/rings and support the linear first isomorphism/correspondence theorems.

**10.3 Endomorphisms.** `Module.End K V` is an algebra where multiplication is composition. This lets polynomials be evaluated at an endomorphism via `aeval`. Eigenspaces are kernels of `φ - a • 1`; eigenvalue predicates, minimal polynomials, and characteristic polynomials are tied together by root theorems. In finite dimension, roots of the minimal polynomial correspond to eigenvalues, and Cayley–Hamilton is the statement that evaluating the characteristic polynomial at the operator gives zero.

**10.4 Matrices, bases and dimension.** Concrete matrix notation is useful for exploration, but matrices are optimized for proof rather than numerical computation. The `Matrix` type wrapper ensures matrix multiplication instances rather than pointwise function multiplication. Inversion is totalized; meaningful inverse identities require invertibility evidence. Bases are internally linear equivalences with finitely supported coordinate functions. `Basis.constr` and `Basis.ext` are often more useful than explicit coordinates. `toMatrix` is the bridge once bases are finite. `Module.finrank` is a natural-number interface under finite dimensionality; general dimension is a cardinal `Module.rank`, with universe lifts needed when comparing basis index types in different universes.

## Failure Recovery Notes

- If scalar multiplication notation is ambiguous, specify the base ring/field in theorem arguments or type ascriptions.
- If a matrix theorem accidentally uses pointwise multiplication, ensure the expression has `Matrix m n R` type rather than an unwrapped function type.
- If `finrank_pos_iff` cannot infer the field from `Nontrivial V`, supply the named ring argument explicitly.
- If a coordinate proof grows large, step back to basis extensionality, span induction, or linear-map equality before continuing entrywise.

## Worked Example
To show a linear invariant such as determinant does not depend on the chosen basis (for bases indexed by the same finite type), represent an endomorphism in basis `B` and basis `B'`. Express the change-of-basis matrices using `toMatrix` applied to the identity linear map. Use composition-to-matrix lemmas to relate the two representations through multiplication by change-of-basis maps; take determinants; use multiplicativity and the fact the change-of-basis maps are inverses. The operational point is to prove coordinate invariance via the functorial map-to-matrix API rather than entry-by-entry determinant manipulation.

## Key Takeaways
1. Work with bundled linear maps/submodules before coordinates.
2. Use span, quotient, basis, and direct-sum universal properties as construction tools.
3. Use `Basis.constr` to define maps from basis values and `Basis.ext` to prove equality.
4. Enter matrices only when a finite coordinate calculation is the natural representation.
5. Distinguish finite dimension (`finrank`) from general cardinal dimension (`rank`).
6. Add type ascriptions/named field arguments when coercions or the base field become ambiguous.
