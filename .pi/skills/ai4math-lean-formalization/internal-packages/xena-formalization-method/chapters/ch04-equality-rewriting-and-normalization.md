# Chapter 4: Equality, Rewriting, and Normalization

## Core Idea

Many Lean failures described informally as “it knows these are the same” come from conflating different equality layers. Diagnose the layer first, then choose `rfl`, `change`, rewriting, extensionality, conversion, or an explicit isomorphism/transport theorem.

## Equality Layers

### 1. Syntactic identity

Two expressions have the same written/elaborated form. Rewriting searches for matching occurrences, so syntax matters. Associativity, inserted coercions, or alternative definitions can prevent an expected match.

### 2. Definitional equality

Expressions reduce to the same term by the type theory's computation rules. `rfl` can close a reflexive target up to such reduction; `change` lets you replace the goal by a definitionally equal one; `exact` also accepts a term whose type is definitionally equal to the target.

Definitional equality is implementation-sensitive. For example, one direction of a recursively defined arithmetic identity may reduce while the symmetric statement needs induction. This asymmetry has little mathematical significance and should rarely become a public API dependency.

### 3. Propositional equality

A theorem proves `a = b`. Rewriting uses such proofs to substitute equals inside predicates/functions. Equality is itself inductively generated by reflexivity; its eliminator supplies substitution, symmetry, transitivity, and the familiar rewrite behavior.

### 4. Extensional or structural sameness

Functions, sets, subobjects, and structures often have dedicated extensionality theorems. Instead of unfolding their representations, reduce equality to equality of observable components.

### 5. Isomorphism / canonical comparison

Two objects may only be naturally or canonically isomorphic. Do not silently substitute one for the other. A “canonical” isomorphism earns its usefulness through proved compatibility: naturality, operation preservation, commuting diagrams, or universal properties. If downstream work uses extra structure not controlled by that property, prove another bridge.

## Rewrite Workflow

WHEN `rw` fails:
1. print or inspect the exact subterm;
2. check orientation of the equality;
3. normalize harmless definitional wrappers (`change` or targeted simplification);
4. expose the relevant field/coercion if hidden;
5. use an extensionality lemma if the target is structural;
6. use `convert` when theorem and target are mathematically aligned but differ by small equality obligations.

WHEN `simp` fails or explodes:
1. decide the canonical normal form first;
2. orient simplification lemmas toward it;
3. remove rules that expand and then contract each other;
4. keep noncanonical transformations explicit;
5. test the rule set on units, associativity, inverses, and nested terms.

## Subsingletons and Unique Data

Mathematical uniqueness does not imply definitional identity. Two terms of a subsingleton type are propositionally equal by a theorem. Code carrying truncated/existence data can therefore make `exact` fail even when “there is only one possible thing.” Use the uniqueness theorem or `convert` rather than expecting reduction.

## Anti-patterns

- Unfolding a high-level object until equality becomes a low-level mess.
- Adding global simp lemmas merely to fix one proof.
- Treating a canonical isomorphism as literal equality without compatibility proof.
- Depending on definitional equality in a public theorem when an API lemma would be more stable.

## Validation Checkpoint

When equality tooling misbehaves, record both sides after elaboration and normalization instead of relying on pretty-printed resemblance. Check whether the mismatch disappears by definitional reduction, needs a theorem, needs extensionality, or only has an isomorphism. For rewrites, verify direction and the exact subterm that should match; for simplification, confirm the chosen normal form is stable. If transporting across an isomorphism, list the operations or predicates that must commute with the transport. A canonical name or construction does not discharge those compatibility obligations automatically.

## Key Takeaways

Ask “same in which sense?” before changing tactics. Stable formal mathematics relies on explicit equality/transport APIs, with definitional equality used as an implementation convenience rather than a universal mathematical principle.
