# Glossary

**`#check`** — Ask Lean for the type/signature of a term; use it before guessing an API or overloaded notation. (Ch 02, 04)

**`#eval`** — Evaluate a computable expression during exploration. (Ch 02, 05)

**`apply`** — Use a theorem/constructor whose conclusion matches the goal, replacing the goal with its premises. (Ch 03, 06)

**`apply?`** — Ask Lean/Mathlib for candidate declarations that can close or transform the current goal. (Ch 04, 06)

**Cauchy sequence** — A sequence whose points eventually become mutually close; completeness turns Cauchy behavior into convergence. (Ch 07)

**Continuous linear map** — A linear map bundled with continuity; the right object for operator norms and Fréchet derivatives. (Ch 09)

**Curry–Howard correspondence** — Read propositions as types and proofs as terms inhabiting those types. (Ch 02, 05)

**Definitional equality** — Equality Lean can reduce by computation/unfolding; `rfl` succeeds when both sides reduce to the same term. (Ch 05, 06)

**Dependent function** — A function whose result type may depend on its input; represented by a `∀`/Pi type. (Ch 02, 05)

**EReal / ENNReal** — Extended-number types that add infinite values; finite-case conversion to reals often requires explicit side conditions. (Ch 07)

**Filter** — An abstraction for “eventually” and modes of approach; limits and continuity are expressed through `Tendsto`. (Ch 07)

**Fréchet derivative** — A local linear approximation expressed by a continuous linear map with a small-o remainder. (Ch 09)

**Goal** — The type of the term still to be constructed; its outer form usually determines the next proof move. (Ch 02, 03)

**InfoView** — VS Code pane showing the tactic state, including local context and current goals. (Ch 02)

**Inductive type** — A type generated by constructors; eliminate with pattern matching/cases and prove recursive properties with induction. (Ch 05, 06)

**Instance / typeclass** — A mechanism for inferring structure and overloaded operations from types; inspect it when notation or algebraic operations resolve unexpectedly. (Ch 05, 08)

**`let`** — Introduce a local definition whose definitional identity remains available for reduction/unfolding. (Ch 06)

**`have`** — Introduce a proved local fact; useful for intermediate propositions and proof blueprints. (Ch 03, 06)

**Mathlib** — Lean’s mathematical library; prefer its public theorem/API layer before unfolding mature definitions. (Ch 04)

**Metric space** — A space with a distance; filter convergence can be converted to explicit metric estimates when concrete inequalities are needed. (Ch 07)

**Namespace** — A scope used to organize declarations and avoid name collisions. (Ch 03)

**Normed space** — A vector space with a norm, inheriting metric/topological structure; complete normed spaces are Banach spaces. (Ch 08)

**Proof state** — Local hypotheses plus one or more target types; tactics transform this state while constructing a proof term. (Ch 02, 06)

**`rcases` / `obtain`** — Destructure conjunctions, existentials, structures, or alternatives into useful local components. (Ch 03, 06)

**`rw`** — Rewrite by an equality in the goal or a selected hypothesis; direction and location matter. (Ch 02, 06)

**`simp`** — Simplify using a curated rewrite set; constrain it with `simp only` when broad simplification obscures intent. (Ch 02, 06)

**Structure** — A one-constructor record with named fields; building or projecting fields mirrors conjunction-style reasoning. (Ch 05)

**`Tendsto`** — Filter-level statement that a map sends one mode of approach to another; central to limits and continuity. (Ch 07, 08)

**Tactic** — A proof-construction command that transforms goals and emits a proof term. (Ch 02, 06)

**Universe** — A level used to stratify types and avoid self-containing type paradoxes. (Ch 05)

**Witness** — A concrete term supplied to prove an existential target; after choosing it, prove its property. (Ch 03, 06)
