# 第17章：证明

## Core Idea
证明是由可检查的小逻辑步骤构成的说服性解释。发现证明可以很乱，最终证明应重建清晰依赖。

## Frameworks Introduced
- **小步链**：每一步来自定义、假设、已知结果或明确计算。
- **发现/呈现分离**：探索阶段允许猜、倒推、试错；成稿只保留合法依赖与必要动机。
- **技术库思维**：没有包治百题的算法，但直接、分情况、矛盾、归纳、逆否等模式可复用。
- **可审查性**：读者应能指出每一步为何成立，以及每个假设在哪里用到。

## Procedure
1. 先写待证陈述和允许使用的前提。
2. 探索阶段允许猜测、倒推和试算，寻找中间桥梁。
3. 成稿时只保留合法的正向依赖与必要解释。
4. 最后逐步审计：每个关键断言来自哪里。

## Key Concepts
- **证明**：由可检查逻辑步骤说明一个陈述为何成立的论证。
- **逻辑步骤**：由已知事实按合法规则得到下一事实的推理单位。
- **依赖**：后选择对象允许依赖于哪些先前变量/信息的关系。
- **严谨**：每个关键断言都有足够定义、假设或定理支持。
- **证明技术**：可复用的证明结构，如直接、分情况、反证、归纳、逆否。

## Mental Models
- 把“证明”看作一段可执行的理由链，而非结论前的仪式。
- 遇到“显然”也应能补出关键缺口。

## Anti-patterns
- 把计算结果当作无条件事实。
- 把发现过程原样倾倒给读者，掩盖逻辑主线。

## Worked Example (reconstructed)
探索时可从目标 $a=b$ 倒推到“若能证 $a-b=0$ 就够了”；真正成稿则从假设出发证明 $a-b=0$，随后推出 $a=b$。

## Validation Notes
证明完成后逐句问“这一句由哪条定义、假设或已证结果得到？”；若某一步只能靠待证结论本身，属于循环。能删去细节并保留一条清楚骨架，是理解证明结构的额外证据。

## Key Takeaways
1. 发现可非线性，证明呈现需合法。
2. 每步可追溯。
3. 证明技巧要与命题结构匹配。
