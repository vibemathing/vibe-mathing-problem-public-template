# 第15章：如何阅读定义

## Core Idea
定义要逐字精确掌握，并用例子/非例子压力测试边界。定义中的条件可双向用于识别对象和展开对象。

## Frameworks Introduced
- **对象+条件解析**：先写“被定义的对象是什么类型”，再列出必须满足的全部条件。
- **定义双向使用**：定义常作为 iff 使用：满足条件即可归类；已知属于该类即可展开条件。
- **六类例子检查**：典型、简单、平凡、极端、非例，以及由旧对象构造的新对象。
- **定义动机**：问为什么条件这样选、删一条会出现什么坏对象。

## Procedure
1. 写出被定义对象的类型。
2. 把定义条件逐条编号，并尝试双向使用。
3. 至少造典型例、平凡/极端例和一个近似但失败的非例。
4. 删改一条条件，观察出现什么坏对象，以理解定义动机。

## Key Concepts
- **定义条件**：一个对象要落入定义类别必须满足的各项要求。
- **例子**：满足指定条件的具体对象，用于理解、测试和探索。
- **非例**：看似接近某定义却至少违反一个必要条件的对象。
- **平凡例**：结构极简单、可快速核验定义的例子。
- **极端例**：位于定义允许范围的边界、最小/最大或退化位置，用于暴露条件作用的例子。
- **定义动机**：解释为何选择这些条件、它们排除了什么坏行为。

## Mental Models
- 每学一个定义，至少能造一个例子和一个近似但失败的非例。
- 把条件逐项编号，后续定理应用时逐项核对。

## Anti-patterns
- 只记名称，不记条件。
- 把某个定理中的“若”也当作定义式双向使用。

## Worked Example (reconstructed)
阅读“等价关系”定义时，把任务拆成三项：自反、对称、传递。然后分别造一个关系只满足其中两项来验证三项互不冗余；再看模同余如何同时满足三项。

## Key Takeaways
1. 定义条件要精确。
2. 例子与非例共同刻画边界。
3. 问删改条件会发生什么。
