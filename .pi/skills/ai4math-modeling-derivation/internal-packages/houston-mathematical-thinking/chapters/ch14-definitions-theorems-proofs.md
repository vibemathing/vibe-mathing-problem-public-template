# 第14章：定义、定理与证明

## Core Idea
先分清数学文本中的角色：定义规定术语，定理/命题给出需证明的事实，引理服务于后续，推论从已有结果快速推出，猜想尚待证明，公理是起点。

## Frameworks Introduced
- **角色分类**：读到一个块时先判它是在定义对象、声明事实、提供工具，还是给出证明。
- **证明义务**：只有事实性断言需要证明；定义本身是在规定语言。
- **依赖链**：记录一个结论依赖哪些定义、已证结果与公理，防止循环论证。

## Procedure
1. 先判文本块是定义、定理/命题、引理、推论、猜想还是公理。
2. 若是定义，把条件作为后续可展开接口；若是事实性断言，登记证明义务。
3. 画出当前结果依赖的定义和先前结论。
4. 检查论证是否偷偷依赖了正在证明的结果。

## Key Concepts
- **定义**：规定术语/对象满足哪些条件的数学约定。
- **定理**：已经证明的重要数学陈述。
- **命题**：已经证明或待证明的数学陈述，通常地位较定理轻。
- **引理**：主要用于帮助证明后续结果的辅助定理。
- **推论**：从已知定理较直接推出的结果。
- **猜想**：有证据支持但尚未证明的数学陈述。
- **公理**：理论中作为起点接受的基本假设。
- **证明**：由可检查逻辑步骤说明一个陈述为何成立的论证。

## Mental Models
- 先问“这段文字承担什么功能？”再读细节。
- 名称可能有传统差异，功能比标签更重要。

## Anti-patterns
- 把定义当作需要证明的经验事实。
- 用尚未证明的目标作为自己的前提。

## Worked Example (reconstructed)
若文本说“定义：偶数是能写成 $2k$（$k$ 为整数）的整数”，使用时可直接展开为存在整数 $k$。若随后有“定理：两个偶数之和为偶数”，这才产生证明义务。

## Key Takeaways
1. 识别角色可显著减少阅读混乱。
2. 证明应能追溯到定义与既有事实。
3. 读数学文本时，先识别每个块的角色再决定如何使用。
