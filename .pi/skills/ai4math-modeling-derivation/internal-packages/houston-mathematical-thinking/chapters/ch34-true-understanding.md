# 第34章：真正的理解

## Core Idea
“理解”要用可观察能力验收：能精确复述、造例/非例、迁移、解释依赖、修改条件、总结结构，并向别人说明。

## Frameworks Introduced
- **定义理解清单**：能精确/用自己的话陈述；给典型、平凡、非平凡、非例；陌生处识别；解释动机与相关定理。
- **定理理解清单**：能陈述、应用新情形、理解证明、找弱化假设的反例、知道逆命题/后果/理论位置。
- **证明理解清单**：能复述、指出每个假设使用处、识别结构与技巧、补空白、迁移想法、说明删假设哪里坏。
- **主题理解清单**：能画出概念网络、给关键例、改定义看新理论、在直觉与技术细节间切换、向别人解释。

## Procedure
1. 先选要验收的层级：定义、定理、证明或整个主题。
2. 逐项执行对应能力测试，而非问自己“感觉懂不懂”。
3. 把失败项转换成具体学习任务，如造非例、补证明、找 converse。
4. 隔一段时间在陌生问题上重复测试，确认能迁移。

## Key Concepts
- **理解验收**：用可观察任务验证是否真正理解，而非依赖熟悉感。
- **迁移**：把概念或证明想法用于新的、不熟悉的情境。
- **解释**：能用自己的话说明概念、因果与方法。
- **概念网络**：一个主题中关键定义、定理、例子与其他主题的连接图。
- **关键例**：能集中呈现一个理论多项特征的代表性例子。

## Mental Models
- 把“感觉懂了”换成一组可测试的行为。
- 解释给别人和自造例子是高强度检验。

## Anti-patterns
- 把熟悉感当理解。
- 只会照例题，不会处理陌生情形。

## Worked Example (reconstructed)
对“连续函数”之类新定义做验收：闭书写定义；用自己的话解释；给常见例、边界例、非例；指出一个使用连续性的定理；尝试删改定义中的一个条件并观察后果。做不到的项就是复习路线。

## Key Takeaways
1. 理解必须能被测试。
2. 例/非例、迁移和依赖解释是核心证据。
3. 把不会的清单项直接转成学习任务。

## Connects To
可作为整个 Skill 的最终 SELF_CHECK；第35章给出日常最小习惯。
