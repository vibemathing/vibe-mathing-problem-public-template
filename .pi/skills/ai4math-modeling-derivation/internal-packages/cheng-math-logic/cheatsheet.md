# Cheatsheet — 决策规则

| 看到什么 | 立即做什么 | 不要做什么 | 路由 |
|---|---|---|---|
| “为什么X一定对？” | 改问“X在什么条件下对？”；声明背景；找反例 | 引用权威或“就是这样” | ch01→ch02 |
| “为什么不能做Y？” | 查单位元、逆元、规则冲突；问换世界需牺牲什么 | 把局部限制说成宇宙禁令 | ch02 |
| 定义有奇怪例外 | 先找定义服务的目标；检查生成是否完整、无冗余、唯一 | 只背定义 | ch03 |
| 多个案例似乎同构 | 选抽象滤镜；写保留/忽略特征；再一般化 | 只看相似不看差异 | ch01/ch04 |
| 只有几个样本 | 把趋势当猜想；补逻辑桥梁或反例测试 | 从有限样本断言“永远” | ch03/ch05 |
| 符号公式难懂 | 找产生公式的关系；归一化；换几何/网格表示 | 靠口诀顶替理解 | ch06 |
| 直觉与证明冲突 | 同时审计定义、逻辑与直觉；必要时换表示 | 让直觉直接否决逻辑 | ch04 |
| 图表很“震撼” | 查基线、尺度、透视、投影、线性/对数轴 | 把视觉冲击当数据事实 | ch07 |
| “到底几条边/几个洞？” | 列不同定义→各自求答案→按目的选 | 强迫所有人共享一个定义 | ch08 |
| “A和B相同吗？” | 明确“在哪个方面相同”；写不变量 | 把相等理解成所有属性完全相同 | ch07/ch08 |

## Default workflow

1. **目标**：用户真正想理解、证明、设计还是教学？
2. **背景**：对象、运算、定义、变量域、几何/坐标、判准是什么？
3. **边界**：最小反例在哪里？哪些条件改变答案？
4. **结构**：哪些细节可暂时忽略？基本构成要素和关系是什么？
5. **推导**：逐步逻辑推进，避免反向蕴涵或偷换定义。
6. **换表示**：代数↔几何↔图表；写明必须保持的不变量。
7. **复核**：用第二路线、逆运算、边界例或定义一致性检查。
8. **结论**：只在已声明背景内下结论；信息不足时明确说“不足以唯一判断”。

## Quality bar

优先答案应同时做到：**解释为什么、暴露前提、可推广、可复核、说明失效条件**。如果只能给正确结果却解释不了结构，继续寻找更透明的路线。
