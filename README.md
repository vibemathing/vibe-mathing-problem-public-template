# Vibe Mathing Single-Problem Research Repository

This repository contains one canonical ProblemContract plus a fixed, self-contained Vibe Mathing Harness snapshot. The root [`VERSION`](VERSION) file is the single semantic-version source for the builder, source manifest, generated snapshot, and release checks.

The repository is Pi-native: after project trust and package installation, Pi discovers only the ten project mathematical Skill entries and the pinned `pi-goal-x` extension declared in [`.pi/settings.json`](.pi/settings.json). Goal is a continuation extension, **not** a mathematical Skill; the project defaults are in [`.pi/pi-goal-x-settings.json`](.pi/pi-goal-x-settings.json), its concrete-actor commands and recovery boundary are in [`TEMPLATE_REPOSITORY.md`](TEMPLATE_REPOSITORY.md), and the separate [maintainer Skill](.pi/opt-in-skills/README.md) is explicit opt-in only. Pi's local `.pi/npm/` install cache is Git-ignored, not vendored: `make check-full` verifies its reviewed package bytes when installed and rejects a tracked or modified cache. This checked-in repository is the generic template, not a bound research repository: `problem:template-placeholder` remains an inert draft fixture and no mathematical actor may start here. Live repository admission is recorded separately in [`WEB_REPOSITORY_ADMISSION.json`](WEB_REPOSITORY_ADMISSION.json); the template Web transport remains synthetic until a concrete problem repository receives fresh live receipts. The AI4Math Skills bundle and route 31 complete project-authored internal reference packages through repository-relative registries. They are MIT-licensed and bound to the owner attestation and immutable package tree digests in [`project-authored-package-rights-attestation.v1.json`](governance/control-plane/project-authored-package-rights-attestation.v1.json). Start `pi` from the repository root, verify the `.pi/skills/` entries, and then choose a maintenance or instantiation mode:

- **T1–T9 coordinator (one ChatGPT Project, one problem):** read `AGENTS.md`, then [`WEB_COORDINATOR.md`](WEB_COORDINATOR.md). The coordinator performs fresh-state preflight and emits nine bounded worker prompts; it is not a tenth mathematical lane.
- **Issue-bound research worker:** read `AGENTS.md`, `WEB_BOOTSTRAP.md`, `governance/control-plane/web-context-profile.v1.json`, `HARNESS_SNAPSHOT.json`, `WEB_CONTEXT_BUNDLE.md`, and the Issue-bound Attempt/Route/Obligation. Treat the bundle as a bounded navigation cache; fresh ledgers and live GitHub state win.
- **Local canonical Pi researcher:** read `AGENTS.md`, the frozen ProblemContract, current failed-route memory, and the relevant project Skill only. Local candidate work still has no Evidence/Result admission authority. For an explicitly launched local actor, [`.pi/opt-in-extensions/local-write-guard.ts`](.pi/opt-in-extensions/README.md) is an optional, policy-bound file-tool guard; the generic template loads the Goal package but does not create a Goal, start HookLoop, or activate this guard. One actor has at most one continuation scheduler; the guard has no scheduling authority.

After a concrete repository passes its own admission gates, the Web GPT GitHub channel may own the routine candidate flow end to end: Issue, `web/attempt-*`, candidate file revisions, commits, PR creation/review, check monitoring/rerun, merge, and checkpoint. It cannot create the repository, direct-write protected/truth paths, or admit Evidence, Results, or Solutions. Machine gates and independent mathematical verification remain required for mathematical closure; routine human handoffs do not. Run [`RELEASE-CHECKLIST.md`](RELEASE-CHECKLIST.md) and `make audit-release` before any public release; the audit reports each C01–C10 gate. For this generic template, C05 and C08 are explicitly not applicable; concrete repositories must satisfy them.

## Candidate-only Research OS

The optional [`research/`](research/README.md) Research OS layer records bounded observations, candidate conjectures, refutation/connection references, and verification links next to the existing Problem/Attempt/Obligation/Candidate/Evidence chain. It is permanently non-authoritative and `candidate_only`: it cannot create Evidence, Result, Solution, admission, or mathematical closure. Run `make check-research-os` for its isolated schema, boundary, hash-chain, WAL, and projection checks. The template placeholder is synthetic and must be replaced by a reviewed ProblemContract before real research use.

A repository URL by itself is not a complete bootstrap. The user must direct the coordinator to `WEB_COORDINATOR.md` or the worker to `WEB_BOOTSTRAP.md` so the model reads the frozen contracts instead of guessing from chat memory.
